# Automacon WCS — описание возможностей для коммерческого предложения

**Назначение документа.** Структурированное описание функциональных возможностей платформы **Automacon WCS** (Warehouse Control System) для включения в коммерческие предложения и тендерную документацию. Материал разбит по функциональным блокам и подходит как для целевой выборки (отдельный блок), так и для использования целиком.

**Краткое позиционирование.** Automacon WCS — это enterprise-платформа управления складской роботизацией класса WCS, поставляемая как коробочное решение на серверах заказчика (on-premise). Платформа объединяет в едином контроллере роботов любых производителей по протоколу VDA5050, любую промышленную периферию по ModBus, а также сценарии бизнес-логики, аналитику, дашборды и AI-ассистента для оператора.

---

## 1. Управление парком роботов (VDA5050)

**Назначение блока.** Унифицированное управление транспортными роботами (AGV/AMR) разных производителей в рамках одного парка.

| Возможность | Описание для КП |
|---|---|
| **Полная поддержка протокола VDA5050** | Реализованы версии 1.1, 2.0 и 3.0. Поддерживаются подключение, статусы, заказы, состояния выполнения, ошибки и фабричные сообщения. |
| **Мульти-вендорный парк** | Одновременная работа в одном контроллере с роботами **MiR, KUKA, Omron, Geek+** и роботами других производителей, в том числе локальных. Подключение нового вендора — без изменений ядра системы. |
| **Современные алгоритмы диспетчеризации** | Динамическое назначение задач: ближайший робот, наименее загруженный, по приоритету миссии, с учётом зон, габаритов и заряда. |
| **Управление транспортными заданиями** | FIFO, приоритеты, динамическое перераспределение, пулы роботов под зоны/типы задач, предотвращение взаимоблокировок (deadlock prevention). |
| **Контроль трафика** | Ограничение плотности на участках, динамическое снижение скорости, предотвращение пробок и встречных столкновений на критических ребрах графа. |

**Эффект для заказчика.** Отказ от вендор-локкинга, возможность строить парк из роботов разных производителей и менять их без миграции платформы.

## 2. Управление промышленной периферией (ModBus)

**Назначение блока.** Подключение и управление любым внешним оборудованием склада по индустриальному протоколу.

| Возможность | Описание для КП |
|---|---|
| **Любые ModBus-устройства** | Конвейеры, лифты, ворота, весы, индикаторы, зарядные станции, паллетайзеры, светофоры, датчики и др. |
| **Поддержка ModBus TCP/RTU** | Гибкая настройка таймаутов, политики retry, автоматическое переподключение при сбоях линии. |
| **Эффективный опрос и запись** | Цикличный опрос с настраиваемой частотой; групповое чтение и запись регистров для минимизации нагрузки на шину. |
| **Циклы и события** | Сочетание периодического опроса и немедленной записи по событию из бизнес-сценария. |
| **Отказоустойчивость** | Автоматическое восстановление связи, изоляция сбойных линий, эскалация ошибок диспетчеру. |
| **Симуляция периферии** | Эмуляция ModBus-устройств без физического железа для отладки сценариев. Подтверждено на физическом симуляторе ModBus в полевых условиях. |

**Эффект для заказчика.** Все станочное окружение и инженерные системы становятся частью единого автоматизированного контура наряду с роботами.

## 3. Карта склада и визуализация

**Назначение блока.** Сквозная визуализация физического и логического состояния склада в реальном времени.

| Возможность | Описание для КП |
|---|---|
| **Поддержка мульти-карты в LIF и GeoJSON** | Этажи, цеха, территории. Слои: точки, дороги, станции, динамический слой устройств (роботы, паллетайзеры, зарядные станции). |
| **Режимы 2D и 3D** | Быстрое переключение режимов: в 2D — упрощённые SVG-модели для скорости отрисовки; в 3D — детализированные модели OBJ/MTL и glTF/glb. В обоих режимах — реалтайм координаты и углы поворота. |
| **Масштаб карты до 200 000 объектов** | Подтверждено на реальном складе с 60 000 объектов. |
| **Плавная анимация движения** | Интерполяция позиций — без рывков, корректные углы поворота. |
| **Пользовательские модели устройств** | Подключение собственных 3D-моделей роботов и периферии (в том числе сторонних производителей) с реальными габаритами. |
| **Сквозная навигация «таблица ↔ карта»** | Из любой записи в таблицах миссий, ошибок, устройств, роботов — переход в точку на карте и обратно. Данные обновляются в реальном времени. |
| **Поиск объектов** | По ID, названию, коду; расширяется на дополнительные атрибуты (координаты, статус, заряд, производитель и т. д.). |
| **Автослежение камеры** | Камера автоматически сопровождает выбранный робот в режимах 2D и 3D. |

**Эффект для заказчика.** Диспетчер и техническая поддержка работают в единой картине склада: никаких разрозненных мониторов под каждый тип оборудования.

## 4. История склада и аналитика

**Назначение блока.** Точное воспроизведение состояния системы в любой момент времени и аналитика операций.

| Возможность | Описание для КП |
|---|---|
| **Машина времени по складу** | Полная реконструкция состояния системы: движение роботов, состояние устройств, миссии, ошибки — на любой выбранный момент в прошлом, строго в соответствии с точками изменений. |
| **Плеер движения** | Шкала времени, управление воспроизведением (play / pause / перемотка), регулируемая скорость от 0,1× до 100×. |
| **Дашборды на движке Grafana** | Готовые системные дашборды и нативные виджеты Grafana «под капотом». |
| **Системные виджеты** | Карта, список миссий, карточки и таблицы роботов, журнал ошибок, стартер миссий, состояние периферии. |
| **Аналитические виджеты** | KPI-панели, тренды, sla-отчёты, нагрузочные графики на базе Grafana. |
| **Самостоятельное создание дашбордов** | Пользователь собирает произвольные панели и виджеты без участия разработчиков. |
| **Аудиторская готовность** | Возможность точного разбора инцидентов «постфактум», ретроспективный аудит работы склада. |

**Эффект для заказчика.** Прозрачность работы парка, аудит инцидентов, доказательная база для расчётов SLA и оценки эффективности.

## 5. Сценарии и бизнес-логика

**Назначение блока.** Кастомизация бизнес-процессов склада силами специалистов заказчика без вмешательства в код ядра.

| Возможность | Описание для КП |
|---|---|
| **Визуальный конструктор сценариев (NoCode/LowCode)** | Узлы, связи, ветвления, циклы, вызов подпроцессов; полноценный редактор бизнес-процессов с визуальной отладкой. |
| **JS-блоки** | Расширение логики кастомным кодом: расчёты, фильтрация, обращения к внешним API. Реализация сложных сценариев выбора ячеек, оборудования, ожиданий, передачи транспортного ордера другому роботу. |
| **Web-формы взаимодействия с оператором** | Прямо внутри сценария: диалоги, выбор из списка, ввод данных, подтверждения. |
| **Управление транспортными заданиями** | FIFO, приоритеты, динамическое назначение, deadlock prevention. |
| **Быстрая разработка нестандартных блоков** | Формализованный процесс расширения палитры блоков; разработка достаточно сложного блока — в порядке часов, а не дней. |

**Эффект для заказчика.** Логика склада адаптируется под бизнес силами заказчика; снижаются стоимость и сроки кастомизации.

## 6. Интеграция и API

**Назначение блока.** Встраивание WCS в ИТ-ландшафт предприятия (WMS, ERP, MES, BI).

| Возможность | Описание для КП |
|---|---|
| **REST API со 100% покрытием функциональности** | Документация в формате Swagger/OpenAPI. |
| **Запуск миссий и управление парком из внешних систем** | Создание/отмена миссий, чтение телеметрии, управление парком с учётом прав доступа. |
| **Полный CRUD по всем сущностям** | Стандартные операции создания/чтения/обновления/удаления через API. |
| **Ролевая модель и разграничение доступа** | RBAC на уровне записей: контроль прав пользователей, групп и ролей до отдельных объектов. |
| **Импорт карт из CAD/GIS-систем** | Поддержка форматов LIF и GeoJSON для загрузки готовых картографических данных. |
| **Webhooks/события** | Внешние системы могут подписываться на события склада (миссии, ошибки, состояние периферии). |

**Эффект для заказчика.** Бесшовная интеграция с действующими WMS/ERP, отсутствие изолированных «островков автоматизации».

| Возможность | Описание для КП |
|---|---|

**Эффект для заказчика.** Картография поддерживается силами заказчика, без сторонних CAD/GIS-инструментов и привлечения вендора.

## 12. Multi-agent AI-ассистент

**Назначение блока.** Сокращение нагрузки на оператора и диспетчера за счёт работы с системой на естественном языке.

| Возможность | Описание для КП |
|---|---|
| **Естественно-языковые запросы** | Оператор задаёт вопросы свободной формулировкой («что делал робот 20 минут назад», «куда поехали все роботы», «сколько миссий сейчас в работе»). |
| **Мультиагентная архитектура** | Специализированные агенты: оркестратор миссий, аналитик ошибок, гид по карте, диспетчер; согласованная работа между собой. |
| **Каталог навыков (skills)** | `missions_live_status`, `robot_history`, `errors_overview`, `fleet_routing` и др. Расширяется под нужды заказчика. |
| **Контекстная навигация** | Ассистент сам идёт в телеметрию, плеер истории, журнал ошибок и сводит результат в человеческий ответ. |
| **Action-aware** | Помимо ответа предлагает следующее действие («вывести список роботов с ошибками?»), формируя многошаговый диалог. |
| **Формализованная разработка новых навыков** | Стандартизированный шаблон навыка: инструмент агента + промпт + права. Время вывода нового навыка — порядок часов. |

**Эффект для заказчика.** Радикальное снижение времени на разбор инцидентов и работу с парком; точка масштабирования автоматизации диспетчерской.
